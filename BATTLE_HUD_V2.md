# Battle HUD V2 — scene-first manga layout

## Intent

The battle HUD is treated as a comic-page composition, not as a set of independent debug panels.

The stable composition is:

- **CommandDeck**: top-left tactical commands and current turn state.
- **HeroPanel**: large active-character manga panel below/behind the command deck.
- **InitiativeRibbon**: narrow top-center timeline.
- **ObjectiveBrief**: top-right mission objective.
- **MottoCard**: small paper insert on the right edge.
- **CombatTicker**: compact bottom-left combat feed.
- **UnitDossier**: bottom-right inspected/active unit card.
- **CombatPreview / FacingSelector / ActionBanner**: transient overlays.

## Ownership

`scenes/ui/battle_hud_3d.tscn` owns composition, anchors, proportions, styles and decorative elements.

`scripts/prototypes/spore_battle_board_3d.gd` loads the HUD scene at runtime and binds functional controls only through Godot unique node names (`%TurnLabel`, `%MoveButton`, etc.). It does not depend on a custom HUD global class or on deep hierarchy paths.

This avoids parse-time coupling between the battle controller and the HUD scene while keeping the HUD freely rearrangeable in the Godot editor.

## Functional node contract

The following nodes are unique names in the HUD scene and form the runtime binding contract:

- TurnLabel, InfoLabel, HelpLabel
- MoveButton, AttackButton, FaceButton, EndButton
- PrimarySkillButton, SecondarySkillButton
- InitiativeRibbon, TimelineBar
- LogLabel
- CombatPreview, PreviewTitle, PreviewBody, PreviewConfirmButton, PreviewCancelButton
- UnitDossier, UnitPortrait, UnitTitle, HpBar, HpText, MpBar, MpText, UnitBody
- HeroPanel, HeroPortrait, HeroName
- ObjectiveBrief, ObjectiveTitle, ObjectiveBody
- ActionBanner, ActionBannerTitle, ActionBannerSubtitle
- FacingSelector and the six facing controls

Do not reintroduce hard-coded deep hierarchy paths or a parse-time preload of the HUD scene into `SporeBattleBoard3D`.

## World composition

Mission 1 no longer uses the legacy 253-node `mission1_tile_material_field_3d.tscn` overlay.

Tile texture is generated by the shared tactical-tile shader using per-cell phase variation. The authored forest frame is built from reusable scenes:

- `comic_mushroom_tree_3d.tscn`
- `comic_mushroom_cluster_3d.tscn`
- `comic_ruin_cluster_3d.tscn`
- `comic_forest_floor_3d.tscn`

The camera intentionally centers slightly left of the board so the board is visually shifted to the right, leaving room for the permanent HeroPanel.

## Visual rules

- Environment: almost monochrome, warm paper highlights, hard black ink.
- Saturated color: gameplay accents only.
- UI borders: square, thick, ivory/ink; avoid rounded application-style cards.
- Permanent HUD: asymmetrical.
- Transient overlays: may be centered but should read as comic stamps, not modal windows.
- Avoid world-space labels larger than the units they annotate.
