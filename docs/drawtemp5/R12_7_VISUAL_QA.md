# DrawTemp 5.0 — R12.7 Art & Visual Certification

## Actual shipped path

The Player uses the already-packaged **Jeanne** artwork in
`sporebound/content/art/jeanne/jeanne_atlas.png`. It is not a placeholder
character generated by the viewport.

- **64 × 64 frames**, four directions: south, north, east, west.
- **Idle**: two frames at 280 ms each.
- **Move**: two frames at 140 ms each.
- **Attack**: two frames at 140 ms each.
- **Hit / defeat**: one existing frame per direction.

The existing `jeanne.game.json` manifest binds those animations with the
legacy order `jeanne_move_east`. R4 imports normally use the order
`jeanne_east_move`. `PresentationAssets` now reads *both* without changing
assets, rules, project hashes, save compatibility or replay format.

The shared R3 `RendererController.animationFrame(...)` exposes only a
detached read-only atlas frame to Qt Quick. R12.7's `TacticalBoard.qml`
uses that very same resolver for **move, attack, hit** events. A real
animated sprite replaces the prior temporary humanoid shapes when available;
unknown actors still get the harmless abstract fallback. The idle actor,
atlas cropping, pivot and camera remain owned by `IsoViewport.qml` (R3).
The static idle actor is temporarily hidden during motion, attack and
verified Jeanne hit art; it returns once the presentation clip has ended.

This is **cosmetic only**. Battle outcome, CT, damage, simulation revision,
seeds, saves and tactical recording are never affected by the animation clock.

## Automated gates

```bash
python -m unittest tests_standalone.test_drawtemp5_r127_art -v
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software \
  DRAWTEMP_R127_ARTIFACT_DIR=./artifacts/r127 \
  python -m unittest tests_standalone.test_drawtemp5_r127_visual_qt -v
```

The visual job uses the **actual Qt Quick viewport and packaged
image**, asserting:

1. Both frame samples (idle, move, attack) resolve to authored assets in
   **all four directions** and match the declared atlas regions/pivots.
2. The real Player renders Jeanne's idle frame and resolves the active
   move/attack/hit pose with the R4 asset resolver.
3. The Qt scene changes actual pixels between rest, movement, attack, impact
   and post-cancel rest; captures cannot be null.
4. During a clip the static actor is concealed, and it reappears after
   cancellation (no double figure). Saves and game recordings are identical.
5. The headless R4 runtime/asset regression suite still passes.

The **artifacts** `r127-idle.png`, `r127-move.png`,
`r127-attack.png`, `r127-impact.png`, `r127-restored.png` and
`r127-capture-manifest.json` are uploaded on each matching PR to
GitHub Actions as `drawtemp-r127-visual-candidates-ubuntu`.

The screenshots are **review candidates, not automatically approved goldens**.
This job certifies reproducible asset loading and real pixel changes in
software/offscreen Qt; it does **not** substitute for a human art-direction
signoff, a real GPU frame-time measurement, or accessibility review.

## Manual artistic review — to sign off

- [ ] Jeanne has consistent hair, silhouette, palette and scale from idle to
      move, attack and hit in each of four directions
- [ ] Each two-frame cycle contains genuinely distinct coherent poses;
      especially rear-facing walk and strike (known weak points)
- [ ] The pivot is stable, no foot sliding or unexpected clipping over
      varied terrain elevations; check zoom 0.4×, 1×, 2× and 3×
- [ ] Attack wind-up, contact frame and hit reaction are readable and in the
      right order, even when another command interrupts a clip
- [ ] Enemy silhouettes and atlas fallback do not duplicate, float or blink
- [ ] Animations remain smooth on Windows/macOS/Linux hardware-backed Qt
      (measure p95/p99 frame intervals and avoid excessive sprite cache churn)
- [ ] Audio R11 is synchronized to visible impacts and restored correctly
      after pause, load and transition
- [ ] Capture frames are reviewed and explicitly accepted by art direction;
      only then create separately reviewed golden image baselines

**Certification state: runtime/visual automated gate added; final artistic
signoff still pending human review, complete sprite polish and audio/GPU
quality gate.** Do not mark R12.7 or the full R12 gate as wholly closed
without the checklist above.
